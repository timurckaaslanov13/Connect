# Connect: текущее состояние

## Сделано

- Регистрация, хеширование паролей, вход по JWT, профили, личные чаты.
- Начальные миграции четырёх PostgreSQL-баз; ожидание готовности БД перед API.
- Проверенный запуск на новых томах без изменения старых пользовательских томов.
- Общая отправка HTTP/WebSocket: проверка членства, сохранение и живая доставка.
- Короткие сессии БД в рабочих потоках для message-service; сокет не держит сессию.
- История с курсором after_id, limit 1–100 и составным индексом.
- Единственный личный чат на пару пользователей даже при одновременных запросах.
- Служебный ключ для проверки членства, секреты через .env, генератор конфигурации.
- Redis Pub/Sub: доставка между двумя экземплярами message-service.
- WebSocket-авторизация первым фреймом, таймаут входа, закрытие по истечении JWT.
- Проверка обязательных exp/sub и корректности идентификатора во всех сервисах.
- Коммиты по завершённым этапам; workflow GitHub Actions для регрессионных проверок.

## Проверено локально

- 40 автоматических тестов: JWT всех сервисов, права, обработка сбоев зависимостей,
  история, WebSocket, очистка соединений, таймауты, рассылка и список чатов.
- Все миграции на настоящей PostgreSQL 16: upgrade/check/downgrade/upgrade/check
  в отдельных временных базах, совпадение итоговой схемы с моделями.
- Живой сценарий: три аккаунта, профили, 12 конкурентных запросов одного чата,
  отсутствие дублей, отказ постороннему, отправка HTTP и WebSocket, страницы истории.
- Доставка между двумя отдельными контейнерами через Redis; восстановление после
  перезапуска Redis. При сбое публикации сообщение сохраняется, но клиенту может
  потребоваться перечитать историю после закрытия/переподключения.
- Тестовый стек connect-check использует порты 18000–18004; исходные тома connect_*
  не изменялись. .env.check исключён из Git. Коммиты локальные, push не выполнялся.
- GitHub Actions подготовлен; удалённый workflow ещё не запускался.

## Практические ограничения и следующие этапы

Это рабочая основа мессенджера, а не завершённая социальная сеть.

- Нет полноценного пользовательского интерфейса: пока Swagger и HTML WebSocket-тест.
- Нет refresh/logout/revocation, восстановления пароля и ограничения частоты запросов.
- Redis Pub/Sub не гарантирует доставку после обрыва; восстановление идёт через БД.
  Для гарантированных событий нужен transactional outbox и повторная доставка.
- WebSocket получает события до истечения JWT; если появится удаление участников,
  оно должно также отзывать уже открытые соединения на всех экземплярах.
- Миграции в основном контейнере рассчитаны на один запуск; при масштабировании
  нескольких одинаковых контейнеров нужен выделенный migration job.
- Старые схемы без Alembic требуют проверки и осознанного stamp 0001; дубликаты
  личных чатов миграция обнаруживает, но не удаляет и не объединяет автоматически.
- Перед внешним размещением нужны TLS, резервные копии, ограничения запросов,
  мониторинг и отдельная проверка безопасности. Сейчас порты доступны на localhost.
